# claude-mux - Claude Code マルチプレクサ

[English](../README.md) · [Español](README.es.md) · [Français](README.fr.md) · [Deutsch](README.de.md) · [Português](README.pt-BR.md) · **日本語** · [한국어](README.ko.md) · [Italiano](README.it.md) · [Русский](README.ru.md) · [中文](README.zh-CN.md) · [עברית](README.he.md) · [العربية](README.ar.md) · [हिन्दी](README.hi.md)

すべてのプロジェクトに対して永続的な Claude Code セッションを提供し、Claude モバイルアプリからどこでもアクセスできます。***Managed by Claude!***

## インストール

```bash
curl -fsSL https://github.com/pereljon/claude-mux/releases/latest/download/install.sh | bash
```

セッションを開始:

```bash
claude-mux ~/path/to/your/project
```

インストーラはログイン時に home セッションを自動起動するか尋ねます。同意すると、ログインのたびに保護された Claude セッションが自動起動し、ターミナルを開かなくてもスマートフォンや任意の Remote Control クライアントからいつでもアクセスできます。

これだけです。Remote Control が有効化された永続的でセッション認識型の Claude セッションに入れます。**ここからはすべて会話で操作できます。**

[Homebrew、手動インストール、その他のオプション](../docs/INSTALL.md)

## なぜ必要か

Remote Control はどこからでも Claude Code を使えることを約束していますが、セッション管理なしでは Claude Desktop からでさえ二流のインターフェースです:

- ターミナルを閉じると**セッションが終了**する
- **会話コンテキスト**が自動的に再開されない
- **常時起動のホームベースがない** - 何かを開いたままにしていない限り、スマートフォンを手に取っても何も動いていない
- **Remote Control には起動中のセッションが必要** - RC からセッションを開始することはできない
- **RC セッションではスラッシュコマンドが動作しない** - モデル切り替え、コンパクト化、permission モード変更が不可
- **新しいプロジェクトの開始** - ディレクトリの手動作成、git の初期化、指示ファイル (AGENTS.md または CLAUDE.md) の作成、モデルの選択が必要
- **プロジェクト管理がない** - アイドル状態のプロジェクトの確認や、履歴を壊さずにプロジェクトの名前変更、移動、削除ができない

**claude-mux はセッション管理のギャップを解決します。** Claude Code を tmux でラップしてセッションを永続化し、クラッシュや再起動の後にセッションを自動的に復元し (自動ログインが有効な場合)、Claude が自身のセッションを管理できるようシステムプロンプトを注入し、スラッシュコマンドを tmux 経由でルーティングして Remote Control 上でも動作するようにします。セッションが起動したら、ターミナルからでもモバイルアプリからでも、Claude に話しかけることですべてを管理できます。

## claude-mux セッションでできること

- **クラッシュや再起動でも維持** - ログインし直すとセッションが自動的に復元され、直前の会話を再開する。正常な `/exit` やシャットダウンではセッションは停止したままになり、クラッシュを繰り返すセッションは延々と再起動されず、停止してフラグが付けられる
- **任意のセッションから任意のセッションを管理** - 自然言語でプロジェクトの起動、停止、再起動、一覧表示、コンパクト化
- **どこからでもアクセス** - 全セッションで Remote Control が有効なので、Claude モバイルアプリ、デスクトップアプリ、その他のリモートクライアントがフルインターフェースになる
- **モデルと permission モードの切り替え** - 「Haiku に切り替えて」や「plan モードに切り替えて」と言えば、Remote Control 経由でも Claude が処理
- **新規プロジェクトの作成** - 「my-app という新規プロジェクトを作成して」で、ディレクトリ作成、git 初期化、テンプレートからの AGENTS.md 作成、セッション起動まで完了。テンプレートでプロジェクト間で指示を再利用可能
- **Remote Control 経由でスラッシュコマンドを送信** - `/model`、`/compact`、`/clear` などのスラッシュコマンドを Claude が実行中のセッションにルーティングし、[既知の制限](https://github.com/anthropics/claude-code/issues/30674)を回避。RC は `PreCompact` フックにより `/compact` の後に自動的に再接続する
- **Claude Code のアップグレード検出** - `claude` バイナリが変わると (`brew upgrade` や npm の更新後)、実行中のセッションが再起動して新しいバイナリを読み込むよう通知する。通知は再起動するまでプロンプトをまたいで残るので、見逃しても失われない
- **会話履歴の保持** - プロジェクトの名前変更、移動、再起動でも会話履歴を自動的に保持
- **プロジェクトの整理** - 任意のセッション内からプロジェクトの非表示、名前変更、移動、削除、保護
- **GitHub マルチアカウント対応** - `~/.ssh/config` の SSH エイリアスを検出してセッションに注入し、プロジェクトごとに正しいアカウントを使用
- **プロジェクト指示ファイルとしての AGENTS.md** - `AGENTS.md` が唯一の実ファイルで、Claude Code と Codex CLI が読み取る。「migrate to AGENTS.md」と言うと既存のツリーを `CLAUDE.md` から変換する (まずレポートのみ、コミットはしない)。Claude Code 2.1.277 以降が必要で、それより古いバージョンは `CLAUDE.md` のまま。Gemini CLI は `~/.gemini/settings.json` に `"context": {"fileName": ["AGENTS.md"]}` がある場合のみ読み取る
- **どの言語でも動作** - 会話コマンドはキーワードではなく意図から推測される

## Claude に話しかける

これが claude-mux の日常的な使い方です。各セッションにはコマンドが注入されており、Claude はセッション管理、モデル切り替え、スラッシュコマンド送信、新規プロジェクト作成をすべて会話の中から実行できます。CLI フラグを覚える必要はありません。

```
言う：「status」
セッション名、モデル、permission モード、コンテキスト使用量を報告し、全セッションを一覧表示

言う：「アクティブなセッションを一覧表示して」
動作中の全セッションをステータス付きで表示

言う：「アイドル状態のセッションを一覧表示して」
アイドル状態のプロジェクトのみを表示

言う：「停止中のセッションを一覧表示して」
停止中のセッションのみを表示

言う：「api-server プロジェクトのセッションを開始して」
名前でセッションを開始する。すでに起動中なら何もしない

言う：「web テンプレートを使って mobile-app という新規プロジェクトを作成して」
プロジェクトディレクトリを作成し、git を初期化して、テンプレートを適用し、セッションを起動

言う：「このセッションを Haiku に切り替えて」
ファミリーを最新の具体的な ID に解決し、自身に /model claude-haiku-4-5 を送信

言う：「api-server セッションをコンパクト化して」
api-server セッションに /compact を送信

言う：「web-dashboard セッションを再起動して」
セッションをシャットダウンして再起動し、会話コンテキストを保持

言う：「このセッションを新規で再起動して」
確認を求めた後、新しい会話で再起動 - 再開なし、以前のコンテキストなし

言う：「api-server セッションを kill して」
確認を求めた後、会話をクリアして停止する。次回の起動は再開ではなく新しい会話になる

言う：「このセッションを終了して」
未完了の作業と次のステップを先に保存し、確認を求め (未保存のものがないかも尋ね)、その後新規で再起動

言う：「api-server セッションを plan モードに切り替えて」
plan permission モードでセッションを再起動

言う：「このセッションを yolo モードに切り替えて」
Shift+Tab 経由で bypassPermissions モードに切り替え - 再起動不要

言う：「このセッションのモードは？」
現在の permission モード (default、acceptEdits、plan、bypassPermissions) を報告

言う：「このセッションを Opus に切り替えて」
ファミリーを最新の具体的な ID に解決し、自身に /model claude-opus-4-8 を送信

言う：「このセッションをクリアして」
確認を求めた後、自身に /clear を送信して会話をリセット

言う：「このプロジェクトを非表示にして」
.claudemux-ignore を書き込み、-L 一覧から除外

言う：「このセッションを保護して」
.claudemux-protected を書き込み、tmux マーカーを設定 - シャットダウンには --force が必要に

言う：「このセッションは保護されてる？」
プロジェクトフォルダの .claudemux-protected を確認して報告

言う：「old-prototype プロジェクトを削除して」
チャットで確認後、プロジェクトフォルダをシステムのゴミ箱に移動

言う：「このプロジェクトを my-new-name にリネームして」
セッションを停止し、フォルダ名を変更し、会話履歴を移行して再起動

言う：「これを web という名前のテンプレートとして保存して」
AGENTS.md (または CLAUDE.md) を ~/.claude-mux/templates/web.md にコピー

言う：「check agents migration」/「migrate to AGENTS.md」
(読み取り専用で) AGENTS.md に移行できる CLAUDE.md ファイルを報告し、確認後にツリー全体で名前を変更して、ベースディレクトリ配下の実行中セッションを再起動

言う：「tip」
ヒントを表示 - 同じ日は同じヒント、TIP_MODE=random を設定するとランダム

言う：「ヒントを有効にして」/「ヒントを無効にして」
全プロジェクトで毎日のヒントをオン/オフ

言う：「update claude-mux」
全セッションが再起動される旨を警告し、確認後にアップデートと再起動を実行

言う：「全セッションを停止して」
管理対象の全セッションを正常終了

言う：「help」
会話コマンドの全一覧を表示
```

**これらのコマンドはどの言語でも動作します。** スペイン語、日本語、ヘブライ語など、他の言語で同等の表現を入力しても、Claude は意図を読み取って対応するコマンドを実行します。

**任意のセッション内で `help` と入力すると、コマンド一覧を確認できます。**
